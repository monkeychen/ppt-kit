# PRD v0.1.0 — ppt-kit：图片版 PPT 还原为可编辑 PPTX

## 1. 背景与目标

**一句话**：把 AI 生成的幻灯片图片、NotebookLM 导出的 PDF、PowerPoint 导出的 PDF，转成**文字和形状都能直接改**的 PPTX，渲染出来和原稿肉眼几乎看不出差别。

**对用户的价值**：现在 AI 生成的 PPT 都是“死图”，改一个字只能重新生成或者手工重画。按手工重画一页 15–30 分钟估算（待补数据：需实测 10 页取平均），ppt-kit 要把它缩短到“转换 + 少量修正”，每页 2 分钟以内。

**v0.1.0 范围**：两条输入路径（矢量解析 / 位图识别）+ 文字和形状可编辑 + CLI。图表和 GUI 放到 v0.2.0。

### 对“100% 还原”的定义（全文统一口径）

AI 生成的图本身没有“原始字体”和“原始数据”，像素级 100% 做不到。本项目用两个可测量的维度替代：

| 维度 | 指标 | 测量方式 |
|---|---|---|
| 视觉保真 | 渲染出的 PPTX 与原图的 **SSIM**，以及文字区域的平均像素差 | `render/` 模块自动计算 |
| 可编辑程度 | 原图中的文字和形状，被还原成**原生可编辑元素**的比例 | 合成基准集带标准答案，自动比对 |

## 2. 用户故事

- **US1**：作为培训讲师，我想把 NotebookLM 生成的 PDF 课件转成 PPTX，这样可以改掉里面的错字、换成自己的品牌色，不用重画。
- **US2**：作为内容创作者，我想把 GPT 或 Gemini 生成的单张幻灯片图片转成可编辑页面，这样能把它拼进我已有的 PPT。
- **US3**：作为职场用户，我手里只有同事发来的 PDF（由 PowerPoint 导出），我想拿回一份可编辑的 PPTX，而且文字、字体、颜色、位置都和原来一样。
- **US4**：作为自动化工作流的使用者（agent 或脚本），我想用一条命令批量转换整个目录，并拿到机器可读的质量报告，这样可以自动筛出需要人工复核的页面。
- **US5**：作为职场用户或内容创作者，我手里有一份「图片版 PPTX」（例如从 Canva/Gamma/AI 导出的纯图片幻灯片，或被另存为图片演示文稿的 PPTX），我想直接将其转成文字、形状可编辑的高保真 PPTX，无需手动导出 PDF 或切图。

## 3. 功能需求

### F1 输入加载与路径判定
支持 `.png` / `.jpg` / `.jpeg` / `.webp` / `.pdf` / `.pptx`；PDF 与 PPTX 按页拆分。每一页自动判定走哪条路径：**vector**（有可用矢量文字）或 **raster**（纯位图，或矢量文字不可用）。
- **AC1.1**：输入 6 种格式各 1 个样本，都能成功加载，页数与源文件一致。
- **AC1.2**：PowerPoint 导出的矢量 PDF 判为 vector，NotebookLM 导出的 PDF、单张图片及图片版 PPTX 判为 raster；在 benchmark 已标注样本上判定准确率 100%。
- **AC1.3**：同一个文档里混合了两类页面时，按页分别判定，`report.json` 中每页都记录 `route` 字段。
- **AC1.4**：输入加密 PDF、损坏文件或不支持的格式时，CLI 以非零退出码结束，stderr 输出原因和建议操作（例如“该 PDF 已加密，请先用 `qpdf --decrypt` 解密”）。

### F2 Slide IR（统一中间表示）
用 pydantic 定义页面元素树：页面尺寸、背景、文本框（含段落、文字片段及字体/字号/颜色/粗斜体/对齐/行距）、形状（类型、几何、填充、描边、圆角）、图片（裁剪图 + 位置）、层级顺序、每个元素的置信度和来源。
- **AC2.1**：IR 可以序列化为 JSON 再反序列化，往返结果完全一致（有单元测试覆盖全部元素类型）。
- **AC2.2**：所有坐标都是整数 EMU；单位换算只在 `pptkit/common/units.py` 一处实现（用 lint 规则或测试保证没有其他地方直接写换算常量）。

### F3 PPTX 生成器（IR → PPTX）
- **AC3.1**：生成的文件能被 PowerPoint（基准）、WPS、Keynote 打开，不弹修复或报错窗口；PowerPoint 用 AppleScript 打开并导出验证，WPS 和 Keynote 用界面自动化脚本验证并保存截图（见 D1）。
- **AC3.2**：文字是原生文本框，在 Keynote 里双击能直接编辑；形状是原生形状，能改填充色和尺寸。
- **AC3.3**：生成的 PPTX 页面尺寸等于原图宽高比（16:9 输入对应 13.333in × 7.5in，其他比例按原比例生成）。
- **AC3.4**：元素的前后层级和 IR 中的 `z_order` 一致。

### F4 渲染与对比度量
把 PPTX 渲染成 PNG，和原图计算 SSIM、文字区域像素差，并输出差异热力图。
- **AC4.1**：同一个 PPTX 连续渲染两次，SSIM 差值小于 0.001（保证渲染结果稳定）。
- **AC4.2**：输出每页的 `ssim`、`text_region_mae`、差异热力图路径。

### F5 合成基准集
用代码随机生成 PPTX（随机版式、字体、颜色、形状），渲染成 PNG 和 PDF，同时保存 IR 作为标准答案，用来自动给转换质量打分。
- **AC5.1**：一条命令生成 N 页合成样本，每页附带标准答案 IR。
- **AC5.2**：基准评分输出文字识别准确率（字符级）、文字框位置误差（IoU）、字号误差、颜色误差（ΔE）、形状召回率和精确率、SSIM。
- **AC5.3**：真实样本集不少于 20 页（GPT、NotebookLM、Gemini、PPT 导出 PDF 各 ≥ 5 页），用 manifest 登记。

### F6 矢量 PDF 解析路径
从 PDF 直接提取文字（内容、字体、字号、颜色、坐标）、矢量形状、内嵌图片。
- **AC6.1**：在合成基准的 PDF 子集上，文字内容字符级准确率 ≥ 99.5%，字号误差 ≤ 0.5pt，颜色 ΔE ≤ 2。
- **AC6.2**：同一段落内被 PDF 拆成多行的文字，合并成一个多行文本框；段落合并正确率 ≥ 95%。
- **AC6.3**：矩形、圆角矩形、椭圆、直线还原成对应的原生形状；其他路径还原成自由曲线（freeform）；形状召回率 ≥ 95%。
- **AC6.4**：PDF 里的子集字体名（如 `ABCDEF+MicrosoftYaHei`）去掉前缀并映射到系统字体；本机没装的字体在 `report.json` 里列出缺失字体清单。
- **AC6.5**：渐变、阴影等无法用原生形状表示的效果，降级为图片，并在报告中标记 `degraded`。
- **AC6.6**：合成基准 PDF 子集的平均 SSIM ≥ 0.97（初始目标值，M1 跑出基线后校准）。

### F7 位图路径：文字还原
OCR 定位文字 → 抹掉文字并补全背景 → 叠加可编辑文本框 → 估算字号、颜色、字体、粗细、对齐 → 渲染对比后自动微调。
- **AC7.1**：在合成基准的位图子集上，中英文字符级准确率 ≥ 98%。
- **AC7.2**：文字框位置 IoU 均值 ≥ 0.85；字号误差中位数 ≤ 1pt；颜色 ΔE 中位数 ≤ 5。
- **AC7.3**：抹掉文字后的背景层上，原文字区域不留可见文字残影（用 OCR 复检背景层，检出原文字符的比例 ≤ 2%）。
- **AC7.4**：经过渲染对比迭代后，每页 SSIM 不低于迭代前；迭代最多 N 轮（默认 3），可以通过参数配置。
- **AC7.5**：字体从可配置的候选字体集里选择，默认包含思源黑体、思源宋体、苹方、Arial、Helvetica。

### F8 位图路径：形状与图片分层
- **AC8.1**：纯色填充的矩形、圆角矩形、椭圆、直线、箭头还原成原生形状；在合成基准上形状召回率 ≥ 85%、精确率 ≥ 90%。
- **AC8.2**：照片和复杂插图作为独立图片层裁出，在 PPT 里能单独选中和移动。
- **AC8.3**：置信度低于阈值的元素不还原成可编辑元素，保留在背景层，并在报告中列出（体现“宁可退化，不可错乱”）。

### F9 CLI
- **AC9.1**：`pptkit convert <file|dir> -o <outdir>` 能转换单个文件，也能批量转换目录；每个输入生成 `<name>.pptx` 和 `<name>.report.json`。
- **AC9.2**：支持 `--route auto|vector|raster`、`--pages 1-3,5`、`--max-iter`、`--provider gemini|openai`、`--json`（stdout 只输出 JSON，方便 agent 调用）。
- **AC9.3**：转换过程中显示每页进度和预计剩余时间；`--json` 模式下进度改为输出到 stderr。
- **AC9.4**：没有配置 API Key 时，vector 路径和基于本地 Apple Vision + 分级背景修复的离线 raster 路径照常工作；仅当用户显式开启需要云端 VLM 的增强模式（`--vlm`）而未配 API Key 时报错，并提示设置方法（给出具体的环境变量名）。
- **AC9.5**：单页失败不影响其他页；结束时汇总成功和失败页数，退出码区分“全部成功 / 部分失败 / 全部失败”（0 / 2 / 1）。

### F10 质量报告
- **AC10.1**：`report.json` 包含每页的路由、SSIM、可编辑元素数、降级元素数、低置信元素清单、缺失字体、耗时、模型调用次数。
- **AC10.2**：可以按 `ssim < 阈值` 或 `degraded > 0` 筛出需要人工复核的页面（提供 `pptkit report --needs-review` 命令）。

## 4. 里程碑划分

| 里程碑 | 目标 | 覆盖 | 前端 UI | 外部系统 |
|---|---|---|---|---|
| **M1 地基** | IR、PPTX 生成、渲染对比、合成基准、CLI 骨架；跑通“标准答案 IR → PPTX → 渲染”闭环 | F1、F2、F3、F4、F5、F9（AC9.1/9.4/9.5 骨架） | 否 | PowerPoint（渲染度量，AppleScript）、LibreOffice（备用渲染器）、WPS 和 Keynote（兼容性界面自动化） |
| **M2 位图文字与报告** | AI 生成的图片和 PDF 实现“净空背景 + 可编辑原生文字 + 渲染对比微调”，跑通真实样图 `01-ai-beginner-workflow.jpg` | F7、F9（剩余 AC）、F10 | 否 | Apple Vision OCR、分级背景修复、PowerPoint 渲染器、可选 Gemini VLM |
| **M3 位图形状与图片分层** | 形状（圆角框/胶囊/标签）还原为原生可编辑形状，插图/照片独立裁出分层 | F8 | 否 | OpenCV / 轮廓几何分析、可选 Gemini VLM |
| **M4 矢量 PDF 路径** | PowerPoint 导出的矢量 PDF 高精度直接解析还原 | F6 | 否 | 无 |

**为什么这么排**：M1 先把“打分尺”做出来，后面每一步优化都有数字可比。M2/M3 优先攻克用户最高频、最迫切的 AI 生成位图幻灯片（覆盖 US1、US2，并在真实样图 `01-ai-beginner-workflow.jpg` 上直接验证），而且依托 macOS 原生 Apple Vision 实现离线零配置开箱即用；M4 再补齐矢量 PDF 直接解析（覆盖 US3）。*（变更记录：2026-10-19 M1 验收后经用户确认，将位图还原调整至 M2/M3 优先交付）*

## 5. 非目标（v0.1.0 不做）

- 图表、表格还原为原生对象（放到 v0.2.0）
- GUI 桌面应用（放到 v0.2.0）
- Windows 和 Linux 支持
- 动画、切换效果、演讲者备注

## 6. 决策记录

| 编号 | 问题 | 结论 | 理由与影响 |
|---|---|---|---|
| **D1** ✅ | 兼容性以哪个软件为准 | **以 PowerPoint 为准**（本机 16.114）；WPS 和 Keynote 只要求能正常打开、能编辑 | 实测确认：PowerPoint Mac 的 AppleScript `save as PNG` 会静默失败，但 `save as PDF` 正常（耗时约 2 秒）。因此**打分用的渲染（F4）走「PowerPoint AppleScript 导出 PDF（经沙盒目录 `~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/`）+ PyMuPDF 按目标尺寸转 PNG」**，100% 还原 PowerPoint 原生排版与字体渲染。LibreOffice 降为无 PowerPoint 环境下的备用渲染器，报告标注 `renderer`。WPS 和 Keynote 的兼容性（AC3.1）用 macOS 界面自动化检测无报错弹窗并截图存档。*（变更记录：10:17 定为 WPS，10:38 用户装好 PowerPoint 后改为 PowerPoint 并实测跑通）* |
| **D2** ✅ | OCR 引擎 | **Apple Vision**，做成 adapter | v0.1 只支持 macOS，系统自带、免费、离线、中文效果好；以后支持 Windows 时换成 PaddleOCR |
| **D3** ✅ | 抹掉文字后怎么补全背景 | **分级处理**：① 文字下面是纯色 → 直接填色；② 渐变或简单纹理 → OpenCV 修复（不用下载模型）；③ 照片或复杂背景 → LaMa（ONNX 版本，约 208MB，第一次用到时自动下载到 `~/.cache/pptkit/`，Apache-2.0 协议可以随产品分发）；Gemini 图像编辑作为可选增强 | AI 生成的幻灯片里，大部分文字放在纯色或渐变背景上，前两级就能覆盖，速度最快，也不会改动原图；只有文字压在照片上时才需要 LaMa。对用户来说没有任何手动安装步骤 |
